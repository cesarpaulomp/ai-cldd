SYSTEM OVERVIEW
Sistema para criar e administrar eventos de tipos variados.

The server must:

- Permitir via API criar e administrar eventos.
- Permitir via API a realização de check-in e check-out dos participantes.
- Permitir via API o envio de mensagens para os participantes do evento.
- Gerar tokens JWT para aplicações clientes acessarem a API.
- Gerar uma secret para cada sistema cliente.
- Permitir o rotacionamento de secrets e chaves públicas.

CONSTRAINTS AND HARD RULES

- All API responses MUST be in JSON format.
- O domínio NÃO deve depender de Spring, JPA, Security ou qualquer framework.
- Classes da camada application NÃO devem depender de controllers, entities JPA, repositories Spring Data ou detalhes de infraestrutura.
- Records devem ser usados para tipos de dados recebidos externamente ou enviados externamente.
- Entidades de domínio podem ser classes ou records, conforme a necessidade de identidade, mutabilidade controlada e comportamento de negócio.
- Versões de casos de uso e endpoints só podem ser incrementadas se houver quebra de contrato.

GLOBAL ARCHITECTURAL PATTERNS

- The system MUST follow Clean Architecture principles.
- O fluxo de dependência deve sempre apontar para dentro:
  interfaces -> infra -> application -> domain
- Regras de negócio devem ficar prioritariamente em domain.
- A camada application deve orquestrar casos de uso, sem concentrar regras de negócio centrais.
- A camada infra deve conter apenas implementações técnicas e adaptadores para frameworks e recursos externos.

HTTP AND COMMUNICATION STANDARDS

Allowed response formats:

- JSON only

HTTP status code conventions:

- 200: Successful requests that return data
- 201: Successful resource creation
- 204: Successful requests with no response body
- 400: Missing or invalid required fields
- 401: Authentication failures
- 403: Authorization failures
- 404: Resource not found
- 409: Business conflict or duplicated resource state
- 500: Unexpected internal server errors

Default error response structure:

{
"error": "string"
}

The error field MUST contain a machine-readable error identifier, such as:

- INTERNAL_SERVER_ERROR
- FAIL_TO_CONNECT_TO_DATABASE
- UNAUTHORIZED
- FORBIDDEN
- RESOURCE_NOT_FOUND
- INVALID_REQUEST
- CONFLICT
