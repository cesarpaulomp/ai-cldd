OVERVIEW
Este caso de uso define o modelo de dados para cadastro de aplicações clientes e definição do funcionamento da segurança dos endpoints.

DATA MODEL:
application_client
id (id não sequencial UUID v7)
name (Obrigatório) Nome da aplicação cliente
client_secret - Hash para autorização do cliente no uso dos endpoints
created_at (obrigatório) Quando o registro foi criado
updated_at (obrigatório) Quando o registro foi alterado

EXECUÇÃO:

- Crie os modelos de dados em domain/entities
- Crie as entidades mapeadas em infra/persistence/jpaentity
- Crie as interfaces para as novas entidades em infra/persistence/jparepository
- Crie em resources/liquibase/scripts os scripts para criar as novas tabelas
- Crie um port ApplicationRepositoryGateway para ser usado em casos de uso.
- Implemente o caso de uso ValidateApplicationClientSecret.java. Deve receber uma string (client_secret), o application_client_id e retornar um boolean. True quando o secret informado é igual ao do banco de dados.
- Crie ApplicationRepositoryAdapter.java para implementar o ApplicationRepositoryGateway e fazer a ligação entre o caso de uso e a camada de persistência.
- Em infra/config configure a injeção do caso de uso e suas dependências.
- Crie uma camada de segurança para os futuros endpoints que serão implementados no futuro. Essa camada deve chamar o ValidateApplicationClientSecret para validar se o header authorization contém um basic (Base64) com application_client_id e client_secret válidos. Essa camada deve inserir no contexto (SecurityContext) o application_client_id para facilitar a utilização do dado em endpoints implementados no futuro. Caso a request seja inválida ou o header esteja ausente, retornar 401.
